# P5-03 认证撤销：实现与验收边界

当前状态：IN_PROGRESS。本机运行时支持签名撤销、更新前持久暂存与启动对账；尚无已认证的生产防回退外部存储和分发控制面。

## 使用与数据约束

### 检查点与可信发布协调入口

优先使用存储型入口：`ApplyAndPublishRevocationsAsync(listPath, signaturePath, newCheckpointPath, IRevocationPublicationStore, cancellationToken)`。策略先完成签名/范围/新鲜度校验并立刻阻断授权，再要求存储以原子、持久、幂等方式暂存完整签名文档；暂存确认后才把更新接受到内存、保存不可覆盖检查点并提交路径/Sequence/SHA-256。提交成功或响应丢失时，可用同一存储和新检查点调用 `RetryRevocationPublicationAsync`；同序号同哈希提交是幂等的，低序号或冲突值拒绝。

重启必须调用 `LoadWithRevocationPublicationStoreAsync(...)`。它先恢复存储中的已提交检查点；若发现暂存但未提交的签名更新，则在返回策略前重新验证、接受、生成新检查点并提交。存储损坏、签名无效、检查点不匹配或提交失败均不返回可用于授权的策略。因此进程在暂存后、内存接受前、检查点写入中或提交响应丢失时终止，都不会静默回到旧授权。

`FileRevocationPublicationStore` 是单主机开发和真实进程故障演练实现：状态文件写透后原子换代、Unix权限0600，并校验检查点Hash、单调序号及冲突提交。普通主机文件系统管理员可以把状态和检查点一起回退，目录项/存储控制器掉电语义也未认证，所以它不是生产防回退信任根。生产实现必须由受保护的外部配置/密钥/数据库服务提供同一接口契约，并在目标部署中验证单调条件写、权限、备份恢复和故障语义。

以下回调型入口保留用于既有宿主和迁移：

`ApplyAndPublishRevocationsAsync(listPath, signaturePath, newCheckpointPath, publish, cancellationToken)` 串行化撤销更新、不可覆盖检查点保存和可信恢复锚发布回调。签名、范围及序号验证成功后，策略原子地接受撤销并进入全局授权阻断状态；检查点完整写入并刷新到磁盘后，才调用 `publish(absolutePath, anchor, cancellationToken)`。只有回调成功且取消检查通过，才解除全局阻断；已经撤销的元组永久保留，过期规则照常生效。

回调的宿主契约：将检查点位置及 Sequence/Sha256 原子、持久地发布到独立的防回退可信配置；必须支持相同锚的幂等重试，并拒绝低序号或同序号不同哈希。不能仅在内存里赋值或向普通可回退文件写入后，就宣称满足生产可信发布。回调不得重入同一策略的更新/发布方法（更新锁覆盖整个事务）。回调型入口在接受更新前没有持久暂存，因此不能关闭接受至发布之间的进程终止窗口；生产新接线应使用存储型入口。

写入失败、发布异常、取消或发布结果不确定时，全局阻断保持；原签名历史和撤销集合不回退。使用 `RetryRevocationPublicationAsync(newCheckpointPath, publish)` 创建另一代不可覆盖文件并重试，不需重放已接受的签名清单。仅调用 `SaveRevocationCheckpointAsync` 不会解除阻断。发布方已成功但响应丢失的情况依赖回调幂等性，不允许把不确定当作成功。

同一策略首次接受协调入口更新后，旧的纯内存 `ApplyRevocationsAsync` 被拒绝，避免遗漏持久化；后续使用协调入口。首次签名校验失败不切换模式、不改变原授权。重启仍必须使用受可信恢复锚约束的 `LoadWithRevocationCheckpointAsync`，且宿主应继续使用协调入口，不能退回不读取检查点的普通加载流程。

### 显式内存更新入口

调用 `ProductionRuntimePolicy.ApplyRevocationsAsync(listPath, signaturePath)` 更新同一策略实例。签名为 Catalog 原公钥对应私钥对 JSON 原始字节生成的 RSA-PSS/SHA-256 签名，签名文件采用 Base64。JSON 使用 camelCase，对应 `CertificationRevocationList`：schemaVersion=1、catalogVersion、正整数 sequence、issuedAt、expiresAt、revoked 数组。

每条撤销精确匹配 modelId、40 位 revision、task、runtime 和 sha256:64位 runtimeSha256。范围是绑定平台的策略；同一元组在适用该 Catalog 的平台策略中均会被阻断。输入上限分别为 JSON 1 MiB、签名 16 KiB。错误签名、错误 Catalog、未来签发、过期、非法条目或非递增序号均拒绝，不改变原授权状态。

进程内撤销集合只追加：后续列表遗漏旧条目不能恢复其认证。已接受列表过期后拒绝调用，直到收到更新且有效的列表；已撤销条目仍然拒绝。生产模式的实验性运行开关不能绕过撤销。

缓存会话每次调用复核；普通调用返回前再次复核；流式调用开始枚举与每个事件发出前复核。执行中撤销会阻断后续结果，不追回之前已发出的事件，也不保证底层计算立即停止。直接绕过生产路由使用运行时不受此包装保护。

## 不可覆盖的撤销恢复检查点

`SaveRevocationCheckpointAsync(newGenerationPath)` 保存该时刻的完整原始签名历史，返回 `RevocationCheckpointAnchor(Sequence, Sha256)`。每代使用新文件名，已有文件拒绝覆盖；Unix 新文件权限为0600，写入后刷新到磁盘。宿主须先确认保存成功，再将文件路径与恢复锚发布到独立、不可回退的可信部署配置。返回锚不能从待恢复文件自行计算，否则无法防止整体回放或删减历史。

重启使用 `LoadWithRevocationCheckpointAsync`，传入同一 Catalog、公钥、部署摘要、检查点路径和可信恢复锚。恢复先验证整个文件哈希，再逐条验证原始签名、Catalog范围和递增序号，最后核对序号与锚一致。使用私有新策略恢复，任何一步失败都不会返回部分授权。历史清单允许已经过期以保留撤销集合，但最后清单过期时仍阻断全部调用，必须获得更新清单才能恢复未撤销条目。

上限：检查点16 MiB、4096条历史记录；单条清单1 MiB、签名16 KiB。尚无自动压缩，宿主须在到达上限前处理受控换代，不能删除历史撤销条目规避限制。检查点未保存前的内存更新不会自动持久化；掉电导致文件不完整会拒绝恢复，不提供跨平台目录项持久化保证。Windows目录ACL、独立恢复锚的防回退能力和发布事务须由部署系统提供并实测。检查点功能不是自动分发服务。
