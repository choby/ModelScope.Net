# 模型许可证证据与评审流程

版本：draft-1，2026-09-05。本文定义工程证据流程，不对模型许可权利作法律认定；法务批准待真实负责人提供。

## 每个固定模型的记录

保存 Model ID、完整 Commit、仓库模型卡及 LICENSE/NOTICE 路径与SHA-256、源模型/派生模型关联、下载时权限状态、预期用途、分发方式（服务调用/内部部署/对外分发）、是否需要接受额外条款、依赖许可证及负责人审核结论。

模型卡中的标识仅是来源信息；缺失、other、源/派生不一致或额外使用限制进入 review-required。禁止把下载成功、账号绑定成功、数值认证通过当作使用或再分发批准。

## 流程和发布检查

1. 选择固定Commit，保留原始许可证/模型卡证据，不覆盖先前版本。
2. 技术人员核对模型及转换链、运行时与依赖来源，把不确定项列给负责人。
3. 负责人根据实际用途作出 approved/rejected/review-required 决定，记录时间、角色和依据。
4. 把决定绑定到发布清单版本和模型Commit；范围或Revision变化时重新审查。
5. 未批准的必选模型阻止生产发布；移出发布范围必须显式记录范围变更及相应批准，不能自动缩减目标。
6. 技术认证Catalog和许可审核分别保留。技术Certified不代表许可批准。
