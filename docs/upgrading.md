# 升级与回退手册

## 适用范围

本手册适用于 ModelScope.Net NuGet 包、运行时依赖、模型固定 Revision、签名 Catalog 和撤销清单的受控升级。技术预览阶段不承诺跨预览版本二进制兼容；生产变更必须走灰度与回滚流程。

## 升级单位

以下内容必须形成同一个候选发布记录，不能只替换其中一项后直接全量上线：

- 8 个同版本 ModelScope.Net 包；
- .NET SDK、ONNX Runtime、SkiaSharp 与 gRPC 依赖锁；
- 固定摘要的 llama.cpp/Python Worker 镜像和依赖环境；
- 模型 ID、40 位 Revision、制品 SHA-256、任务和运行时身份；
- 签名 Catalog、撤销清单序号、性能与金标准报告；
- Dashboard/告警门槛和目标平台容量参数。

## 标准流程

1. 创建候选清单，记录旧/新版本、Revision、依赖摘要、目标平台和负责人；禁止移动分支作为发布身份。
2. 在干净环境恢复、构建、测试、打包并运行本地包消费者；执行固定模型金标准、性能门禁、安全负面测试和依赖扫描。
3. 在与生产一致的平台预热候选，不接收业务流量；检查健康、资源、审计和指标名称。
4. 按 0% → 1% → 10% → 50% → 100% 灰度。每一级至少观察批准的请求数和时间窗口，并按任务核对失败率、p95、资源与数值抽样。
5. 只有上一阶段全部通过才进入下一阶段；保存发布证据和签名检查点，避免进程重启后接受旧授权状态。
6. 全量后继续观察批准窗口，再退役旧实例；旧包、模型和运行时制品保留至回退窗口结束。

## 回退触发与操作

出现签名/摘要不匹配、金标准失败、审计写入失败、运行时不可恢复、批准 SLO 超限或安全事件时停止放量。新请求路由回最后一个已批准的稳定发布，等待候选在途请求排空，确认稳定版本的指标和金标准恢复，再撤销或隔离失败候选。

撤销清单只能接受签名有效、序号单调且仍在有效期内的新状态。文件型发布存储只用于单机演练；生产必须使用独立、防回退的可信存储，并在进程启动时完成 pending/committed 对账。不得用旧清单、旧 Catalog 或删除状态文件来“回退”安全决策。

## 数据与协议兼容

- 缓存 Manifest 和固定 Revision Snapshot 在升级前备份引用，Blob 内容继续按 SHA-256 校验；不要覆盖已有发布目录。
- Worker gRPC 协议变化需要新旧客户端/服务端交叉兼容测试；不兼容时并行部署新 Worker，而不是原地替换。
- OpenTelemetry 指标重命名必须同步 `metric-contract.json`、Dashboard、告警规则和运行手册。
- 模型 Tokenizer、预处理、输出标签或 Chat Template 变化均视为行为变更，即使权重文件名不变，也必须重新生成金标准。

## 当前限制

仓库已有本机灰度/回滚与进程故障证据，但没有目标集群、真实防回退控制面、72 小时稳定性或负责人批准。因此本手册是可执行基线，不代表升级能力已通过生产验收。
